# 2.7.0 수동 잔액 관리 및 보고 개선

## 적용

Supabase SQL Editor에서 supabase/APPLY_UPDATE.sql 전체를 실행합니다. 압축 안 changjin-finance-app의 내용물을 CFO 저장소 최상위 폴더에 병합하여 덮어씁니다. public 폴더 안에 전체를 복사하지 마세요. public/config.js를 보존하고 GitHub Commit·Push, Netlify 배포 완료 후 Ctrl+F5로 v2.7.0을 확인합니다.

## MMT·예금 관리

처음 상품을 추가할 때 실제 현재잔액과 확인일시를 입력합니다. 이후 상품 행의 잔액 입력 버튼에서 실제 잔액과 확인일시 두 항목만 수정해 저장합니다. 상세 항목은 정보 수정에서 변경합니다. 입출금과 이자가 반영된 은행·증권사 조회금액을 입력하면 됩니다. 과거 기준잔액을 역산할 필요가 없습니다.

기존 자동연결 상품은 처음 수정하기 전까지 종전 계산잔액을 표시합니다. 수정창에는 계산된 현재잔액이 채워집니다. 실제 금액을 확인하여 저장하면 수동관리로 전환되어 이전 연결 증감이 다시 더해지지 않습니다. 기존 연결 이력은 보존하고 이후 수동관리 상품으로의 신규 연결은 차단합니다. 만기일은 비워둘 수 있습니다. 외화상품은 해당 통화금액을 입력합니다.

같은 MMT가 계좌현황에도 있으면 중복 합산되지 않도록 한 곳에서 관리하세요. 일반 계좌의 수동잔액 수정도 사용할 수 있습니다. 자금이동 거래는 분류만 확인완료하면 수입·지출에서 제외됩니다.

## 담당자 작성 순서

1. 은행자료를 업로드하고 계좌잔액을 대조합니다.
2. MMT·예금의 실제 현재잔액과 확인일을 입력합니다.
3. 거래를 분류하고 확인완료합니다. 예치·회수는 자금이동으로 분류합니다.
4. 향후 급여·매입대금·세금·대출상환·회수예정일을 확인합니다.
5. 경영 대시보드에서 보고 내용을 확인하고 새 보고서를 저장합니다.

## 회장님 보고

통장에 있는 돈, 향후 13주 유입·지급, 추가 필요자금, 이번 결정사항을 쉬운 표현으로 요약합니다. 상세 CFO 분석과 함께 화면·새 보고서에 표시합니다. 오래된 MMT 잔액도 자료 보완 항목으로 표시합니다. 자료가 부족하면 투자 가능을 단정하지 않습니다. 예금 환매대금과 대출상환은 입금·지급 예정에 등록해야 전망에 포함됩니다.

## 장기 미접속

프로그램의 사용자·기기 승인에는 미접속 기간에 따른 자동 잠금 조건이 없습니다. 브라우저의 로그인 세션 유지와 자동 갱신 설정을 사용합니다. 세션이 끝나면 재로그인이 필요할 수 있습니다.

Supabase 무료 플랜은 7일간 활동이 적으면 프로젝트를 일시정지할 수 있습니다. 이 조건은 프로그램 파일로 해제할 수 없습니다. 장기 미접속으로 인한 정지를 막으려면 Supabase 조직의 Billing에서 유료 플랜 적용 여부를 확인하고 필요하면 직접 변경해야 합니다. 현재 운영 프로젝트의 요금제·로그인 만료 설정은 이 업데이트에서 변경되지 않았습니다. 이미 정지된 프로젝트는 Supabase에서 복원 후 접속합니다.

공식 안내 https://supabase.com/docs/guides/platform/free-project-pausing

로그인 기기에서 브라우저 저장정보를 삭제하면 기기 승인을 다시 요청할 수 있습니다. 이 설정은 기존 승인 보안을 유지합니다.
