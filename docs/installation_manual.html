설치 안내 · 01 · 설치 설명서

시작 전에 읽어 주세요

이 설명서는 GitHub Desktop으로 소스를 관리하고 Netlify에 사이트를 올려 둔 담당자를 위한 설치 안내입니다. Supabase는 아직 업무 데이터를 넣지 않은 새 프로젝트를 기준으로 합니다.

완료 목표

프로젝트 URL과 공개 API 키 두 값을 config.js에 입력하고, 통합 SQL을 한 번 실행하면 재무 프로그램을 사용할 준비가 됩니다. 실제 사용에는 계정 생성과 기기 승인이 추가로 필요합니다.

준비물확인할 내용
수정 프로그램 ZIP압축을 풀었을 때 public, supabase, netlify 폴더가 보입니다.
GitHub Desktop현재 Netlify에 연결된 저장소가 선택되어 있어야 합니다.
Supabase 계정새 프로젝트를 만들 수 있는 계정과 관리자 이메일을 준비합니다.
Netlify 계정이미 배포한 사이트의 설정과 배포 내역을 볼 수 있어야 합니다.

설치 흐름: 소스 교체 → Supabase 프로젝트와 관리자 생성 → 통합 SQL 실행 → config.js 수정 → GitHub 반영 → Netlify 배포 → 최초 기기 승인 → 시험 입력.

자동화하지 않는 작업: 서비스 가입, 계정 비밀번호 설정, 이메일 확인, 최초 관리자 기기 승인입니다. 실제 비밀번호나 비밀 API 키는 이 문서와 압축파일에 포함되어 있지 않습니다.

설치 안내 · 02 · 설치 설명서

각 서비스가 하는 일

이름쉬운 설명저장되는 내용
GitHub프로그램 원본 보관함HTML·자바스크립트·SQL 등 프로그램 코드
GitHub Desktop내 컴퓨터 변경사항을 GitHub로 보내는 프로그램내 PC 작업 폴더와 업로드 내역
Netlify직원들이 들어가는 웹사이트화면 프로그램과 공개 설정
Supabase로그인·권한·업무자료 보관소사용자 계정, 법인별 재무자료, 승인된 기기
URL과 API 키는 출입증이 아닙니다

config.js는 사이트 이용자가 볼 수 있는 파일입니다. 공개 API 키를 사용하고, 데이터 접근은 로그인 계정·기기 승인·법인 권한을 모두 확인합니다.

이번 버전은 Netlify의 SUPABASE_SERVICE_ROLE_KEY 등 별도 연결 환경변수가 필요하지 않습니다. 관리자 업무도 Supabase의 권한 확인 함수를 통해 처리합니다. 공개 환율 조회 기능만 Netlify Function을 이용합니다.

Netlify 주소에 접속하면 로그인 또는 기기 승인 안내 화면은 표시됩니다. 등록되지 않은 기기에서 회사 재무자료를 열람·수정하지 못하도록 제한하는 구조입니다. 사이트 주소 자체를 외부에서 열지 못하게 하는 네트워크 차단과는 다릅니다.

기기는 사용자 계정 + 사이트 주소 + 브라우저 프로필을 기준으로 구분합니다. 같은 PC라도 Chrome과 Edge는 별도 등록 대상입니다.

설치 안내 · 03 · 설치 설명서

기존 소스를 안전하게 교체하기

  1. GitHub Desktop에서 현재 배포한 저장소를 선택합니다. Repository → Show in Explorer로 작업 폴더를 엽니다.
  2. 기존 작업 폴더를 다른 위치에 복사해 보관합니다. 이 복사본은 프로그램 원본 백업이며 Supabase 업무자료 백업은 아닙니다.
  3. 새 ZIP을 별도 폴더에 압축 해제합니다. changjin-finance-app 폴더 안의 내용을 기존 저장소 루트에 복사합니다. 루트는 public 폴더와 netlify.toml이 놓이는 위치입니다.
  4. 단순 덮어쓰기는 삭제된 옛 파일을 남깁니다. 아래 파일과 폴더가 기존 저장소에 남아 있다면 제거합니다. .git 폴더는 지우지 않습니다.
  5. 기존 docs 폴더의 옛 설명서는 별도로 보관한 뒤 새 docs로 교체합니다. 옛 안내에 따라 여러 SQL을 다시 실행하지 마세요.

netlify/functions/_shared.mjs

netlify/functions/restore-backup.mjs

GitHub Desktop의 Changes에서 변경·추가·삭제 파일을 확인합니다. 이 단계에서는 아직 Commit과 Push를 하지 않아도 됩니다. config.js 설정이 끝난 뒤 함께 올리시면 됩니다.

설치 안내 · 04 · 설치 설명서

Supabase 프로젝트와 관리자 만들기

  1. Supabase에 로그인하여 New project를 선택합니다. 프로젝트 이름과 데이터베이스 비밀번호를 정하고, 회사 사용 지역에 적합한 리전을 선택합니다. 생성이 끝날 때까지 기다립니다.
  2. Authentication → Users로 이동합니다. Add user 또는 Create user에서 관리자 이메일과 충분히 긴 비밀번호를 입력합니다. 이메일 확인 완료 옵션이 있다면 직접 생성하는 관리자 계정에 적용합니다.
  3. 계정이 목록에 나타나는지 확인합니다. 이 이메일은 다음 페이지의 SQL에 정확히 동일하게 입력해야 합니다.
  4. Authentication의 로그인 제공자 설정에서 이메일·비밀번호 로그인을 사용할 수 있도록 확인합니다. 누구나 가입하는 Allow new users to sign up 옵션은 끄세요. 계정은 담당자가 관리 화면에서 생성합니다.
  5. Authentication → URL Configuration에서 Site URL에 실제 Netlify 사이트 주소를 입력합니다. Redirect URLs에도 동일 사이트의 루트 주소를 등록합니다. 예: https://회사사이트.netlify.app/
  6. 비밀번호 재설정 메일을 사용하려면 실제 수신 시험을 합니다. 기본 발송 서비스의 제한에 걸리면 회사용 SMTP를 설정해야 하며, SMTP 비밀번호는 config.js에 넣지 않습니다.
이 단계에서는 SQL을 아직 실행하지 않습니다

관리자 로그인 계정을 먼저 만들어야 통합 SQL이 해당 이메일을 찾아 관리자 권한을 부여할 수 있습니다.

Supabase와 Netlify 메뉴 이름은 화면 개편에 따라 일부 달라질 수 있습니다. 이메일 로그인, 사용자 목록, URL 설정이라는 항목의 기능을 기준으로 찾아 주세요.

설치 안내 · 05 · 설치 설명서

SQL 파일 전체를 한 번 실행하기

  1. 압축파일의 supabase/INSTALL_ALL.sql을 메모장 또는 코드 편집기로 엽니다.
  2. 파일 위쪽의 CHANGE_ME@example.com을 방금 만든 관리자 이메일로 바꿉니다. 작은따옴표는 그대로 둡니다.
  3. Supabase 왼쪽 SQL Editor → New query를 엽니다. 파일 내용 전체를 복사해서 붙여 넣습니다. 다른 SQL 파일을 먼저 실행하지 않습니다.
  4. Run을 한 번 누릅니다. 성공하면 결과에 “설치 완료”와 최초 기기 승인 안내가 표시됩니다.
  5. Table Editor에서 companies에 삼코·삼천산업·창진에스씨가 생성되고, profiles의 관리자 이메일 행에 role이 admin인지 확인합니다. 회사명이 다르면 실제 명칭에 맞게 companies의 name을 수정합니다.
begin;
select set_config(
  'finance.install_admin_email',
  '실제관리자이메일@회사도메인',
  true
);

-- 위 예시만 실행하지 마세요.
-- INSTALL_ALL.sql의 전체 내용이 필요합니다.
오류가 나면

오류 내용을 기록하고 원인을 수정한 뒤 파일 전체를 다시 실행하세요. 이 파일은 하나의 트랜잭션으로 구성되어 중간 오류 발생 시 이번 실행의 변경이 취소됩니다. 같은 버전 재실행을 시험했습니다. 기존 다른 프로그램 DB를 합치는 용도로는 사용하지 마세요.

이메일만 맞으면 관리자 역할, 기본 법인, 기본 분류, 테이블, 권한, 기기 검증, 결재, 백업 기능까지 함께 생성됩니다. 최초 기기의 승인값은 다음 단계에서 별도로 변경합니다.

설치 안내 · 06 · 설치 설명서

config.js 두 값 입력하기

  1. Supabase 프로젝트의 Connect 또는 Settings → API Keys에서 Project URL과 Publishable key를 확인합니다. 기존 프로젝트의 anon 키도 사용할 수 있습니다.
  2. 내 PC의 public/config.js를 엽니다. 아래 두 값만 실제 값으로 교체하고 저장합니다.
  3. URL은 https://프로젝트식별자.supabase.co 형식으로 입력합니다. 이번 버전은 기본 Supabase 도메인을 대상으로 합니다.
  4. API 키는 sb_publishable_로 시작하는 공개용 키를 권장합니다. service_role 또는 sb_secret_로 시작하는 비밀키는 사용하지 않습니다. 프로그램도 이러한 키를 거부합니다.
window.FINANCE_CONFIG = Object.freeze({
  supabaseUrl: 'https://프로젝트식별자.supabase.co',
  supabaseAnonKey: 'sb_publishable_실제공개키'
});
자주 하는 실수수정 방법
따옴표·쉼표 삭제예시의 문법을 유지하고 문자열 안쪽 값만 바꿉니다.
데이터베이스 접속주소 사용postgresql로 시작하는 주소가 아니라 Project URL을 사용합니다.
Netlify 주소를 입력config.js에는 Supabase URL을 입력합니다.
관리자 비밀키 사용공개용 키로 교체합니다. 이미 공개한 비밀키는 Supabase에서 폐기·재발급합니다.

config.js는 공개 정보만 포함하므로 별도의 Netlify 연결 환경변수를 추가할 필요가 없습니다. 각 직원이 URL과 키를 따로 입력할 필요도 없습니다. 직원은 동일한 사이트에서 로그인 후 기기 승인을 받습니다.

설치 안내 · 07 · 설치 설명서

GitHub 반영과 Netlify 배포

  1. GitHub Desktop의 Changes에서 config.js와 INSTALL_ALL.sql, 삭제된 옛 함수 파일들을 확인합니다. 비밀번호·secret key·업무 백업파일이 포함되지 않았는지 확인합니다.
  2. Summary에 “기기 승인 및 통합 SQL 적용”처럼 변경 내용을 입력하고 Commit to 현재브랜치를 누릅니다.
  3. Push origin을 눌러 GitHub에 전송합니다. 이 단계가 끝나야 Netlify가 새 소스를 가져갑니다.
  4. Netlify의 해당 사이트 Deploys 화면에서 새 배포가 시작되는지 확인합니다. 연결된 저장소와 배포 브랜치가 GitHub Desktop에서 올린 곳과 같아야 합니다.
  5. 배포 설정은 Base directory를 저장소 루트로 두고, Publish directory는 public, Functions directory는 netlify/functions로 설정합니다. netlify.toml이 이 값을 제공합니다.
  6. 이번 버전은 프런트엔드 별도 빌드가 필요 없는 정적 프로그램입니다. 기존 Netlify 화면에 다른 빌드 명령이나 배포 경로가 지정되어 있다면 이번 구성과 맞추세요.
  7. Published 또는 성공 상태가 확인된 후 사이트를 엽니다. 오류가 있으면 Deploy log에서 첫 오류부터 확인합니다.
배포 후 예전 화면이 보이면

Ctrl+Shift+R로 새로고침하고 탭을 닫았다가 다시 여세요. 예전 서비스워커 캐시는 새 버전이 정리합니다. 사이트 저장정보 전체를 삭제하면 기기 인증값도 지워져 재승인이 필요합니다.

배포 주소를 나중에 바꾸면 브라우저 저장 공간도 달라집니다. Supabase의 Site URL·Redirect URLs를 수정하고 새 주소에서 기기를 다시 등록해야 합니다.

설치 안내 · 08 · 설치 설명서

최초 관리자 기기 승인하기

  1. 배포된 사이트에서 관리자 이메일과 비밀번호로 로그인합니다. 처음에는 재무 화면 대신 기기 등록 안내가 나오는 것이 정상입니다.
  2. 기기 이름에 “재무팀 관리자 PC / Edge”처럼 실제 사용자를 구별할 수 있게 입력하고 등록 신청을 누릅니다.
  3. 화면의 기기 식별번호 전체를 기록합니다. 상태는 승인 대기입니다.
  4. Supabase의 Table Editor에서 registered_devices를 엽니다. id가 기록한 식별번호와 같은 행을 찾습니다. user_id가 Authentication → Users에 표시되는 관리자 UUID와 같은지 함께 확인합니다.
  5. 해당 행의 status를 pending에서 approved로 바꾸고 저장합니다. 다른 행은 수정하지 않습니다. token_hash는 기기 인증용 해시이므로 복사하거나 바꾸지 마세요.
  6. 프로그램 화면으로 돌아와 승인 여부 다시 확인을 누릅니다. 오늘 할 일 화면이 열리면 성공입니다.
  7. 관리자 설정에서 내 기기가 승인 상태인지 확인합니다. 이후 직원 기기는 이 화면에서 승인·철회할 수 있습니다.
처음부터 자동 승인하지 않는 이유

처음 로그인한 사람이나 첫 등록 신청자를 자동으로 관리자로 만들면 원치 않는 기기가 승인될 수 있습니다. 첫 기기는 Supabase 관리 권한을 가진 담당자가 직접 확인합니다.

관리자 기기를 모두 잃었을 때도 같은 방법으로 새 기기 신청을 확인해 승인합니다. 분실한 기기는 즉시 revoked로 바꾸세요. 기기 토큰을 다른 PC에 복사하는 방식으로 복구하지 않습니다.

설치 안내 · 09 · 설치 설명서

직원 등록과 배포 후 시험

  1. Supabase Authentication → Users에서 직원 이메일·비밀번호로 로그인 계정을 만듭니다.
  2. 프로그램의 관리자 설정 → 사용자 등록에서 같은 이메일을 입력하고 성명·역할·법인 권한을 저장합니다. 로그인 계정 생성과 업무 권한 지정은 서로 다른 단계입니다.
  3. 직원이 자신의 PC·브라우저로 로그인하여 기기 등록을 신청합니다.
  4. 관리자는 신청자에게 표시된 기기 식별번호를 직접 확인한 뒤 관리자 설정에서 그 기기를 승인합니다.
  5. 직원은 승인 여부 다시 확인을 누릅니다. 허용된 법인과 메뉴가 나타나는지 확인합니다.
시험 항목통과 기준
미승인 브라우저로그인은 가능하나 기기 안내만 표시되고 재무자료는 표시되지 않음
