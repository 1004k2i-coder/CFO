업무 시작과 기본 원칙

이 프로그램은 3개 법인의 계좌·은행거래·입출금 예정·금융상품을 정리하고, 재무보고와 결재 이력을 함께 관리하는 웹 프로그램입니다. 자동 회계전표 생성이나 은행 실시간 잔액 수집 기능은 아닙니다.

업무 주기담당자가 할 일
매일 시작로그인 → 법인 선택 → 오늘 할 일에서 미확인 거래·기한 경과·결재 대기 확인
자료 입력계좌 잔고 기준일 확인 → 은행 파일 업로드 → 거래 분류와 예정 연결
보고 전기준일·미확인 거래·중복계좌·외화환율 점검 → 보고서 작성
결재결재함에서 내용 확인 → 승인 또는 사유를 적어 반려
업무 마감수정 이력 확인 → 필요 시 관리자 업무 백업 → 로그아웃
가장 먼저 법인을 확인하세요

상단 법인 선택은 조회 범위를 정합니다. 전체 법인은 조회 권한이 있는 회사들의 합계이며, 실제 입력 시에는 대상 법인과 계좌를 구체적으로 선택합니다.

기기 승인은 이 브라우저에서만 유효합니다. 공용 PC에서 로그인 상태를 유지하지 마세요. 담당자가 바뀌거나 기기를 분실하면 관리자가 계정과 기기 권한을 정리해야 합니다.

역할주요 사용 범위
관리자사용자·법인 권한·기기 승인·분류·전체 업무 백업·복원

현업 담당자담당 업무의 업로드·거래·예정 입력

감사자조회·보고서·변경 이력 중심

역할은 메뉴와 재무업무 범위를 정하고, 법인 권한은 어느 회사의 자료를 사용할 수 있는지 정합니다. 역할만 바꾸고 법인을 지정하지 않으면 원하는 자료가 나타나지 않을 수 있습니다.

법인별 권한의미
read / 조회허용된 역할 범위에서 조회
contribute / 현업 입력예정과 은행거래 입력 등 현업 업무
finance / 재무 관리재무 역할과 함께 부여할 때 계좌·금융상품 관리
manage / 전체 관리해당 법인 관리 수준. 시스템 관리자 역할과 같지는 않음
주의할 조합

일반 현업 역할에 manage만 부여해도 시스템 관리자가 되지 않습니다. 전체 백업과 기기 승인은 관리자만 수행합니다. 모듈별 세부 메뉴 권한은 원본 호환용 데이터 구조이며, 이 버전의 관리자 화면에서는 역할·법인 권한을 사용합니다.

사용자 삭제는 업무 이력과 충돌할 수 있으므로 비활성화를 사용합니다. 비활성화는 재무자료 접근을 막으며, 로그인 계정 자체를 정지하려면 Supabase Authentication에서도 처리합니다.

계좌·예금·대출 등록하기

  1. 상단에서 해당 법인을 선택하고 계좌·대출·예금 메뉴로 이동합니다.
  2. 계좌 등록 화면에서 은행명·계좌명·통화·현재잔고·필수보유현금을 입력합니다. 계좌번호는 가능한 한 마스킹해 기록합니다.
  3. 현재잔고가 언제 기준인지 확인합니다. 과거 은행 파일을 올리면 프로그램 잔액도 과거 기준으로 바뀔 수 있으므로 날짜를 반드시 대조합니다.
  4. 예금·대출 등 금융상품은 상품종류, 은행, 원금·현재가치, 금리, 시작일·만기일, 환금 가능일, 담보 여부를 입력합니다.
  5. 외화 금융상품은 통화와 환율을 확인합니다. 자동 환율을 사용하더라도 회계 평가용 고시환율인지와는 별개입니다.
  6. 중도 해지가 불가능하거나 담보 제공 중인 예금을 즉시 사용 가능한 현금처럼 판단하지 않습니다.
중복 합산 예방

하나의 예금을 계좌 잔고와 금융상품에 동시에 입력하면 유동성 판단에서 중복으로 볼 수 있습니다. 어느 항목에서 관리하는지 회사 기준을 정하고 보고 전 확인하세요.

원본 프로그램의 현금계좌 합계는 입력 잔액 중심입니다. 외화 통장 전체를 자동 원화 환산하는 회계 원장으로 간주하면 안 됩니다. 외화는 금융상품 환율 적용과 구분해 관리하고 대시보드 금액을 검산하세요.

필수보유현금은 급여·세금 등 지급 전에 남겨 둘 내부 기준 금액입니다. 이 값을 낮추면 경고가 줄지만 실제 현금이 늘어나는 것은 아닙니다.

은행 파일 업로드하기

  1. 은행 사이트에서 거래내역 엑셀 또는 CSV를 내려받습니다. 원본 파일은 별도로 보관합니다.
  2. 프로그램의 은행자료 올리기 메뉴에서 대상 법인과 대상 계좌를 선택합니다. 법인을 바꾸면 계좌를 다시 선택합니다.
  3. 파일 선택 또는 끌어놓기로 업로드합니다.
  4. 분석 결과에서 거래일시·입금·출금·잔액·내용이 맞는지 은행 원본과 대조합니다. 미리보기는 최대 50건입니다.
  5. 법인과 계좌를 다시 확인하고 검토 후 가져오기를 누릅니다.
  6. 반영 건수와 중복 제외 건수를 기록합니다. 이후 확인할 거래 메뉴에서 분류를 검토합니다.
지원 형식현재 기준
은행 거래내역헤더에 거래일시·입금액·출금액이 있는 양식. 적요·내용·잔액·메모 등을 사용
기존 재무 입력양식자료구분·법인명으로 시작하는 기존 양식
과거 자금계획서기존 조달 및 지출 계획 형식
기존 HTML JSON기존 재무현황표의 corpNames·corps 구조 백업
모든 은행 양식을 자동 지원하지는 않습니다

이번 수정은 연결·접근통제·설치 구성에 관한 것입니다. 다른 은행의 열 이름이 다르면 자동으로 인식하지 못할 수 있습니다. 필요한 열을 맞춘 사본으로 소량 시험 후 사용하세요.

업로드는 여러 단계로 저장됩니다. 중간 오류가 나면 일부 행과 원본 파일이 이미 저장됐을 수 있습니다. 이력과 실제 반영 건수를 확인하고 재시도하세요. 같은 계좌의 동일한 원본 거래는 중복 식별값으로 걸러집니다.

거래 분류와 예정 연결하기

  1. 확인할 거래에서 상태를 미확인으로 두고 조회합니다.
  2. 거래처·적요·메모를 읽고 추천 분류가 맞는지 판단합니다. 추천은 키워드 일치 결과이며 자동으로 정확성이 보장되지 않습니다.
  3. 확정 분류를 선택하고 담당자를 지정합니다. 필요하면 대응하는 입금·지급 예정을 연결합니다.
  4. 확인을 누른 뒤 확인완료 상태로 바뀌는지 확인합니다. 여러 건을 선택해 일괄 확인할 때에는 각 행을 먼저 검토합니다.
  5. 이력 버튼으로 변경 전·후 값을 확인합니다. 오분류는 수정 사유를 업무 기록에 남긴 뒤 바로잡습니다.
내부이체 확인

법인 내부 계좌 간 이동은 외부 수입·지출과 구분해야 합니다. 한쪽 통장에서 출금되고 다른 통장에서 입금된 동일 거래를 실제 매출 또는 비용으로 판단하지 마세요.

입금·지급 예정에서는 날짜, 거래처, 금액, 방향, 확률, 중요도, 담당자를 등록합니다. 실제 은행거래가 확인되면 연결하거나 완료 상태로 바꾸어 중복 전망을 줄입니다.

예정 금액과 실제 금액이 다르면 원인을 확인하세요. 분할 입금·수수료·환차이 등은 일대일 연결만으로 설명되지 않을 수 있어 메모와 별도 검토가 필요합니다.

거래 화면은 한 번에 최대 500건을 조회합니다. 화면 엑셀 내려받기를 전체 데이터 백업으로 오해하지 마세요. 대량 자료를 장기간 운영할 경우 페이지 단위 조회 개선과 별도 데이터베이스 백업을 계획해야 합니다.

보고서 작성과 결재

  1. 검토·보고 메뉴에서 보고서 종류·대상 법인·대상 기간·제목·요약을 입력합니다.
  2. 잔액 기준일, 금융상품 환율, 미확인 거래, 기한 경과 일정을 검토합니다.
  3. 결재 요청 시 결재자를 순서대로 지정합니다. 결재자는 활성 계정이어야 하고 해당 법인 권한과 적절한 역할이 있어야 합니다.
  4. 제출 후에는 결재 상태를 일반 자료 수정으로 바꿀 수 없습니다. 결재함의 승인·반려 기능을 사용합니다.
  5. 결재자는 앞 순서의 승인 여부를 확인한 후 내용을 검토합니다. 반려할 때는 수정 이유를 적습니다.
  6. 작성자는 반려된 내용을 보완하고 다시 제출합니다. 재제출 시 결재선이 새로 만들어지고 기존 처리 내용은 감사 이력으로 남습니다.
  7. 최종 승인된 보고서는 보관 처리할 수 있습니다. 보고 버전과 변경 이력을 함께 관리합니다.

approved / 승인정해진 결재 완료

보고서 스냅샷은 보고 작성 시점의 요약 데이터입니다. 이후 은행자료가 수정됐다고 과거 승인 보고서의 금액이 자동으로 최신 수치로 바뀐다고 가정하지 마세요.

대시보드 읽는 방법

표시 항목읽는 방법
현재 가용자금등록한 계좌 잔고를 바탕으로 표시. 기준일과 통화를 먼저 확인
30일 최저잔고등록된 예정 일정에 따라 앞으로 잔고가 가장 낮아지는 지점
추가 확보 필요예상잔고가 필수보유현금 기준에 미달하는 부분
즉시·30일 유동화금융상품의 입력된 환금 조건을 바탕으로 보는 참고 금액
법인별 자금현황각 법인의 현재잔고·예정 입금·지급·부족액 비교
월별 전망입력된 월별 계획 자료의 합계. 실제 거래와 자동으로 항상 일치하는 원장은 아님
대표 보고 전에 확인할 네 가지

① 잔고 기준일이 같은가 ② 예정 중 이미 완료된 거래가 남아 있는가 ③ 외화·예금이 중복 합산되지 않았는가 ④ 법인 간 이동을 외부 현금흐름으로 잘못 보지 않았는가

전체 법인 합계는 각 법인 입력값을 모은 관리용 수치입니다. 연결회계 기준의 내부거래 제거와 연결재무제표를 자동으로 만드는 기능은 아닙니다.

환율 조회는 외부 공개 서비스를 사용합니다. 제공처 장애·인터넷 차단·서비스 변경으로 실패할 수 있습니다. 실패 시 금액을 임의로 확정하지 말고 담당자가 기준 환율을 확인해 입력합니다.

데이터가 많아지면 Supabase 응답 행수 제한과 프로그램 조회 한도가 영향을 줄 수 있습니다. 보고서 합계는 주기적으로 원본 엑셀·은행 내역과 대조하세요.

기기와 사용자 관리

  1. 관리자 설정의 접속 기기 승인에서 신청 계정·기기 이름·식별번호를 확인합니다.
  2. 기기 이름만 믿지 말고 실제 신청자가 보고한 식별번호 전체와 일치하는지 확인합니다.
  3. 승인하면 해당 계정의 해당 브라우저가 허용됩니다. 계정별 기기는 최대 20개이며, 한도에 도달하면 관리자가 목록을 정리해야 합니다.
  4. 분실·퇴사·공용 기기 사용 종료 시 철회합니다. 철회 후에는 다음 데이터 요청부터 접근이 차단됩니다. 이미 화면에 보인 자료나 내려받은 파일까지 지워지지는 않습니다.
  5. 퇴사자는 사용자 비활성화와 기기 철회를 함께 처리합니다. 이메일 로그인 계정 정지도 Supabase에서 별도로 진행합니다.
  6. 관리자 PC를 교체하면 새 PC에서 등록 신청 후 기존 승인 관리자 기기에서 승인합니다. 기존 기기가 없으면 설치 설명서의 최초 관리자 승인 절차를 따릅니다.
기기 제한의 범위

브라우저에 저장된 무작위 인증값을 사용하는 방식입니다. 하드웨어 인증서·보안칩 기반의 물리적 PC 고정은 아닙니다. 로그인 정보와 브라우저 저장정보가 함께 복제되면 복제된 환경을 완전히 구별하지 못할 수 있습니다.

더 엄격한 기기 보안이 필요하면 회사 관리 단말, 기기 인증서, 접근 게이트웨이 또는 단말 관리 제품을 추가해야 합니다. URL과 공개 API 키 두 값만으로 물리적 기기를 강하게 인증할 수는 없습니다.

인증값은 사용자 계정에 연결됩니다. 다른 직원이 같은 브라우저에서 로그인하더라도 그 직원 계정의 기기 승인이 별도로 필요합니다. 시크릿 창, 브라우저 초기화, 사이트 주소 변경도 재승인 대상입니다.

업무 백업과 복원

  1. 관리자 설정 또는 관리자 대시보드의 전체 백업을 누릅니다. 내려받은 JSON을 접근 제한된 회사 폴더에 보관합니다.
  2. 파일의 format이 changjin-finance-backup-v2인지 확인합니다. 백업은 브라우저 다운로드 폴더에 저장되므로 공용 PC에 남겨 두지 않습니다.
  3. 복원 전에 현재 데이터도 새로 백업합니다. 업무 담당자에게 복원 중 자료 수정을 중단하도록 알립니다.
  4. 관리자 설정의 백업 복원에서 이 버전의 JSON을 선택하고 확인합니다. 동일 ID의 업무자료를 덮어쓰고 신규 ID는 추가합니다. 백업에 없는 기존 행은 삭제하지 않습니다.
  5. 복원 성공 후 법인·계좌·거래 건수·대표 금액·결재 이력을 대조합니다. 다른 프로젝트로 옮기는 경우 원래 사용자 UUID 등 참조가 맞아야 하므로 별도 이전 작업이 필요합니다.

전체 시스템 백업과 구분

화면의 전체 백업은 업무 데이터 백업입니다. 재해 복구에는 Supabase 데이터베이스 백업과 Storage 원본 파일의 별도 보관이 필요합니다. 백업 주기와 보존기간은 회사 기준으로 정하세요.

대용량 백업은 응답 크기·메모리·실행시간 제한으로 실패할 수 있습니다. 큰 데이터베이스는 Supabase의 별도 DB 백업 절차를 사용하고 정기 복구 시험을 하세요.
